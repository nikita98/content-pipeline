## Скиллы / команды

Команды: все скиллы помечены `user-invokable: true` (кроме virality, humanizer, social-listening, competitor-positioning, cross-platform-distribution, utm-campaign-plan, x-thread-strategy — у них этого поля нет; проверить, как это влияет на вызов как /команды). Отдельных slash-команд (commands/) нет.

Формат большинства скиллов: front matter (name, description с триггерными фразами, argument-hint, license: MIT, metadata) + разделы "When to use / What you'll need / Instructions" с готовым промптом в блоке кода + "Honesty" + "Next".

### Подробно: ключевые скиллы

#### content-factory (скилл-оркестратор)

Алгоритм (порядок в SKILL.md):
0. CONNECT (один раз): подключить Apify MCP (разбор рила), Composio MCP -> Instagram (публикация и DM), убедиться, что есть Remotion. Если чего-то нет — СТОП и попросить пользователя подключить; ключи не искать и не переиспользовать.
0.5. ai-brain: вспомнить голос и прошлые победители (если подключён).
1. FIND+STUDY: через Apify разобрать рил-образец (или предложить 3 проверенных формата ниши, пользователь выбирает).
2. viral-hook-writer: 10 хуков, ранжирование; выбирает пользователь или Claude.
3. Заполнить 9 boxes из virality на реальных фактах бренда (пустые боксы не выдумывать), затем reel-scripter: сценарий 30-45 с в голосе пользователя.
4. reel-builder + Remotion (+ Seedance через Runway) -> реальный mp4 с экранной карточкой CTA.
5. caption-and-hashtags: подпись, ярусные теги, первый коммент с кодовым словом.
6. POST: пауза на OK пользователя, затем Composio публикует. Если "wait" — только stage.
7. Composio + comment-responder: кодовое слово "вживую" (комментарий -> публичный ответ + DM, 24/7).
8. ai-brain: сохранить победивший хук/формат.
Цикл: 3 раза в день, ротация угла (результат/доказательство, how-to, контрариан), разное время суток.
Структура вывода: свободная, "показывай вывод каждого шага до перехода"; жёсткой схемы файлов нет. Паузы: выбор формата и перед публикацией.
Правила: моделировать формат, не слова; хук несёт 80% (кульминация ~1.5 с, работает без звука); каждая строка получает визуал; публичный ответ без ссылки (ссылка только в DM); CTA должен реально выполняться; "Never fake a render or a post".
Замечание: нумерация шагов в схеме (0-9) и в тексте промпта (0-8) не совпадает.

#### viral-hook-writer

Алгоритм: собрать тему, аудиторию, желаемую реакцию; прогнать один промпт.
Вывод: 10 хуков по 7 углам (смелое/контрариан; "если вы...; делайте"; ошибка/"хватит"; число+выгода; разрыв любопытства; результат-вперёд; вопрос о боли). Для каждого — версия 3-5 слов на экран. Отметить 3 для теста первыми с пояснением в одну строку.
Правила: до 12 слов, разговорный язык, без воды и хэштегов. Совет: генерировать 10, тестировать 2-3. Подсказка про Obsidian: брать лучшие хуки из vault.

#### hook-mining (единственный скилл со скриптом)

Алгоритм:
1. Вход — CSV с реально сработавшими хуками (Sandcastles/аналитика/хуки конкурентов из agent-reach или reel-analyzer). Имена колонок непредсказуемы, руками не парсить.
2. `python skills/hook-mining/mine_hooks.py hooks.csv [--top 40]` (есть `--selftest`). Скрипт автоопределяет колонку хука (слова hook/title/caption/text/headline) и метрики (view/play/score/like/engagement/reach/performance), ранжирует, раскладывает по 12 паттернам (result-proof, time-bound, contrarian, secret-gap, listicle, how-to, warning-fear, newsjack, comparison, question, curiosity-tease, plain-statement) по регулярным выражениям, отмечает power words (словарь ~50 английских слов), пишет `hooks.mined.json` (hook_column, metric_column, total, buckets, power_word_frequency).
3. Ремикс (делает модель): на каждый хук 3-5 вариантов. Фиксируется: паттерн, порядок клауз, конкретность (число остаётся числом), ритм, напряжение, точка зрения. Меняются только "заряженные" слова, замены брать из power_word_frequency, не из тезауруса.
Правила: никогда не публиковать хук дословно; не менять структуру; число в ремиксе должно быть ВАШИМ и реальным; сначала ранжировать, потом майнить; малые корзины с высокой эффективностью важнее больших средних. Таблица "failure modes" в файле.
Передача: -> viral-hook-writer (ранжировать) -> reel-scripter.
Ограничения для нас: регулярки и словарь только английские; зависимость — Python 3 стандартной библиотеки (csv, json, re, collections, pathlib), без pip. Для русского потребуется переписать PATTERNS и POWER.

#### reel-scripter

Вход: идея/хук, платформа, аудитория, цель, голос. Структура: HOOK 0-3 с; CONTEXT 3-8 с; VALUE 8-30 с (3 быстрых конкретных бита, "show, don't lecture"); PAYOFF+CTA последние 5 с. Вывод: двухколоночный скрипт [SPOKEN] | [ON-SCREEN], ~140 слов, по строке B-roll на бит, 2 альтернативных CTA. Совет: прочитать вслух и сократить на 20%.

#### reel-analyzer

Вход: ссылка/файл/транскрипт + кадры. Вывод (6 пунктов): 1 HOOK (точный текст на экране + произнесённый, почему останавливает); 2 BEAT STRUCTURE (все биты по порядку, речь + картинка, тайминги); 3 PACING; 4 VISUAL TECHNIQUE; 5 WHY IT WORKS (2-3 переиспользуемых приёма); 6 MY REMAKE (план в одну строку). Правило: моделировать технику, не копировать слова. Примечание: в Claude Code нужно самому дать кадры и транскрипт (agent-reach скачивает и делает транскрипт, а извлечение кадров явно не описано, проверить).

#### carousel-builder

Вход: идея, аудитория, цель. Структура: 8-10 слайдов. Слайд 1: заявление/вопрос <8 слов. Слайды 2-N: одна мысль, жирная строка + не более двух поддерживающих. Предпоследний: резюме/чек-лист для скриншота. Последний: единственный призыв. Дополнительно: подпись (хук повторён иначе), визуальная заметка на слайд, место CTA и почему. Правило: если слайду нужно 3 строки, это два слайда. Рендера слайдов в картинки в этом скилле нет (viral-carousel лишь упоминает "HTML to PNG").

#### competitor-teardown

Вход: хэндл или 5-10 постов с просмотрами/лайками/комментариями (agent-reach может собрать). Вывод: 1 WINNERS vs REST (выше медианы, общий признак); 2 HOOK PATTERN (шаблон для заполнения); 3 STRUCTURE; 4 CADENCE; 5 THE GAP (что просят в комментариях, но не делается); 6 MY THREE (3 рила на эту неделю). Правило: даём паттерн, не копию.

#### humanizer (вендор blader/humanizer, v3.1.0, 397 строк)

Алгоритм: пометить приметы (сильнейшие первыми) -> черновик -> проверка (не добавлены/не потеряны факты, имена, числа) -> финал. Режимы: вставленный текст (черновик + оставшиеся паттерны + финал), файловый (правит только прозу, код и YAML не трогает), embedded (только финальный текст). Если есть образец стиля пользователя — он приоритетнее правил (в т. ч. правило о тире).
Паттерны (26, по группам): A Staging (1 "не X, а Y"; 2 однострочные закрывашки; 3 "глубокие" афоризмы; 4 разбег перед мыслью; 5 спор с никем); B Ритм (6 тройки; 7 повтор начал предложений; 8 тире — в финале их не должно быть; 9 стопки оговорок; 10 дефисы; 11 пассив); C Инфляция (12 слова-маркеры ИИ: delve, pivotal, tapestry и т. п.; 13 раздутая значимость; 14 "associated with"; 15 -ing-довески; 16 рекламный язык; 17 заимствованный авторитет; 18 избегание is/are/has); D Форматирование (19 жирный как украшение; 20 декоративные заголовки/эмодзи; 21 фигурные кавычки); E Остатки чата (22 "I hope this helps"; 23 дисклеймеры о знаниях; 24 повтор заголовка в первой фразе; 25 текст о документе вместо темы); F Не тот читатель (26 пересказ контекста тому, кто его знает). Раздел "When not to act".
Источник правил: Wikipedia "Signs of AI writing". Ограничение для нас: чисто англоязычные примеры и списки слов; для русского нужен свой список (рус. ИИ-штампы, канцелярит, тире).

#### dm-script-writer

Вход: ключевое слово, ресурс, оффер. Вывод: 1 MESSAGE ONE — выдать ресурс без питча, коротко, должно заработать ответ; 2 THE QUESTION — один квалифицирующий вопрос в конце; 3 BRANCHES — следующее сообщение для: интересно / не сейчас / не подходит / нет ответа; 4 THE HANDOFF — где вводить звонок/ссылку; 5 TONE — подстроиться под стиль написавшего. Правило: каждое сообщение до 950 символов. Замечание про Instagram: приватный ответ на комментарий работает один раз, дальше нужен ответ пользователя. Цель — "booked call or sale", но оплаты как шага нет.

#### cta-writer

Вход: рил/сценарий, желаемое действие (follow / DM keyword / save / click). Вывод: 1 ONE ASK (если названо несколько — выбрать одно и объяснить); 2 THE REASON LINE (строка-причина перед призывом); 3 THE ASK (дословно, голосом и на экране); 4 KEYWORD (легко набрать, не исправляется автокоррекцией, не использовалось недавно); 5 PLACEMENT (в рил или в подпись); 6 DELIVERY CHECK (что должно быть готово; если нет — "не запускать этот CTA"). Правило: обещать только то, что реально отправится.

#### analytics-readout

Вход: вставленные инсайты + цель (reach/saves/leads/follows). Вывод: 1 THE METRIC THAT MATTERS (и от каких цифр отвлечься); 2 VS MY MEDIAN (всё против своей базы); 3 WHERE IT BROKE (провал ~3 с = хук, ~12 с = середина, в конце = CTA); 4 TWO ACTIONS; 5 WHAT I CAN'T TELL. Правило: каждая цифра из вставленных данных, ничего не оценивать, "not enough signal" допустимо. Источник данных: вручную или Ootto MCP (его нет в репо).

#### Также важны (не из списка, но влияют на карточку)

Сильно привязан к нише автора (Claude + Instagram) и приводит его цифры.

## Слабые места

1. Качество промптов. Обычные 12 скиллов "рабочие" — один шаблон-промпт на 1-2 КБ без проверки результата, без примеров вывода; плюс 18 строгих скиллов (stricter: evidence boundary, hard rules, failure modes). Два стиля в одном репо. Промпты задают "роль" и список пунктов; формат выхода — свободный текст/таблицы, без схемы (YAML/JSON) для передачи следующему шагу.
2. Нет связности. Данные между скиллами передаются только копированием в диалоге; нет общего паспорта бренда, банка идей, статуса идей, ID постов.
3. Англоязычность. Все триггеры, промпты, список power words, humanizer-паттерны — английские; agent-reach — китайский. Русскоязычные запросы могут не вызвать скилл по description (проверить).
4. Привязка к Instagram/Reels: кодовое слово -> комментарий -> DM по правилам Instagram (отправка приватного ответа один раз), хэштеги, Stories, обложка сетки, safe area Instagram. Telegram, Threads не затронуты; VK нет.
5. Заявленное и реальное расходятся: "run for REAL by calling tools directly" в content-factory — это описание, не реализация; конфигов MCP, шаблонов Remotion, ключей и кода публикации в репо нет. "Whole reel factory" в README = в основном текстовые шаги плюс абзац про рендер.
6. Метаданные: plugin.json говорит 13 скиллов, в репо 55; README "30 Instagram skills" — перечислено 33; 18 скиллов в README отсутствуют; версия 1.4.0 у плагина, но у скиллов 1.0.0; у части скиллов нет `user-invokable`/`license`/поля `version`.
7. Часть цифр из README (36 369 просмотров, 560 комментариев, 31,1% глубины скролла) — маркетинговые ссылки на блог, проверить нельзя; "262 posts, 3.5M views" из virality — самоотчёт автора.
8. content-factory: рассинхрон нумерации шагов (в схеме 0-9, в промпте 0-8). reel-builder: стоимость Seedance "$6-12 за рил" и разделение "$20 / $599 tier" — это коммерческая модель Ootto, не техническая.
9. Нет тестов и CI; единственный скрипт имеет selftest, но не запускался (по заданию).
10. Humanizer 32 КБ в одном SKILL.md — большой контекст при каждом вызове (проверить, подгружается ли целиком).
11. install.sh копирует `cp -R "${dir}"*` — не копирует скрытые файлы внутри папок (в репо таких нет); путь только ~/.claude/skills; нет проверки перезаписи.
