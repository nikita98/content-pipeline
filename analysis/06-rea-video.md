## Шаги нашего плана, которые покрывает
- Шаг 1 (ресёрч конкурентов, разбор их видео): основное попадание. Разбор структуры, хука, сюжетной линии (`narrative.role/point`, `story.hook`), таймлайн по шотам, ритм, субтитры (SRT/ASS), транскрипт (ASR, но см. раздел про русский).
- Шаг 7 (раскадровка): частично. Таймлайн по шотам, storyboard.jpg, план пересъёмки по шотам, промпты по модели.
- Шаг 6 (сценарии Reels/Shorts): косвенно. `video/content.md` даёт структуру референса, которую рекомендуется сохранять, меняя содержание.
- Шаг 8 (генерация): частично, только через capsule-cinema (платные модели Китая). Аватар/голос для русского не проверялись.
- Шаг 10 (монтаж): код-шоты — текстовые дорожки и раскладка для Remotion; сам Remotion-проект НЕ генерируется (docs/en/cli.md, таблица «Конвейер»: Reconstruct = частично). В README заявлен «Remotion project» для кодовых видео — расхождение, проверить.
- Шаг 11 (проверка качества): `compare REF REMAKE` сравнивает нарисованный слой, `assemble` выдаёт сравнительное видео; сводной оценки по всем шотам нет.
- Шаг 9 (нарезка длинного видео): не покрывает по назначению. Есть `moments` (поиск ярких моментов) и `drive` (сегменты под танцы) — это анализ чужого ролика, а не нарезка своих. Проверить, годится ли `survey` (склейки) как основа.
- Шаги 0, 2–5, 12–15, ★: не покрывает.

Скилл (SKILL.md, name: rea-video) — алгоритм агента:
1. `rea-video --help`; при отсутствии — references/setup.md.
2. `rea-video memory` (предпочтения/исправления).
3. `rea-video [--env-file .env] decompose ref.mp4 -o out/ref [--vlm] --lang <zh|en>`.
4. `rea-video summary out/ref/breakdown.json` (метки низкой уверенности, строка `VLM:`).
5. Чтение пакета по уровням для экономии токенов: VIDEO.md (~2 тыс. токенов) -> video/timeline.md -> video/shots/NNN.md и кадры -> тематические video/*.md. breakdown.json и report.md не читать.
6. Если агент видит изображения: `review` -> смотрит картинки (priority=high обязательны) -> заполняет review_answers.json -> `apply-review --by <имя>`.
7. Самопроверка: storyboard.jpg, audio.png, shots/shot_XXX.jpg (первый/средний/последний кадр), `tiles` для детальной проверки, cast, звук по stems, реальные материалы, упаковка; после правок повторный apply-review.
8. Ответ по references/output-template.md: вывод одной фразой, содержание, сюжетная линия, план пересъёмки, таблица шотов, упаковка, звук, реальные материалы, неопределённости, путь к report.html.
9. Пересъёмка по запросу: `remake-run --dry-run`, подтверждение пользователя, затем платный запуск.
Запреты в скилле: не судить по стилю картинки; текст в кодовых шаблонах — не наложение; не называть материалы пользователя ИИ; отсутствие метаданных не доказывает «не ИИ»; платную генерацию без подтверждения не запускать.
Язык выбора: явный от пользователя -> язык вопроса -> `lang` из memory -> по умолчанию китайский.

## Как определяет «снято / ИИ / код»
Двухслойно: детерминированная криминалистика (CV, считается всегда, офлайн) + необязательная VLM/агент. Правило слияния: сильные сигналы инструмента не перетираются, один источник мнения не может превратить «ИИ по fps-повторам» в «съёмку».

11 классов (references/taxonomy.md) с порогами:
- live_action: шум сенсора σ>1, временной шум >0.8, доля неизменных пикселей <0.55, ручная тряска, нативные 60 fps.
- ai_video: текстура без шума сенсора, повтор кадров 24->30 или периодичность интерполяции, плавная камера; на кадрах искажённые пальцы/текст. Интерполяция ИИ до 60 fps оставляет периодичность резкости (`sharp_period_ac>0.45`).
- avatar: неподвижная камера, анфас, двигаются рот и голова.
- cg_3d: стабильная геометрия и материалы, фон меняется от кадра к кадру.
- code_render: плоские блоки >20%, менее 70 цветов, много прямых линий, фон неподвижен, нет материальных текстур.
- screen_capture: крупные светлые интерфейсы, мелкий плотный текст, низкая насыщенность, скролл.
- still_motion: жёсткое преобразование, >95% инлаеров, остаток <0.3 px, нет следов 24 fps.
- static_hold: >85% кадров полностью повторяются.
- anim_2d, stop_motion, film_footage: только визуально (VLM/агент); подтверждаются, только когда модель и агент согласны, иначе «требует проверки».
- Склейки: пик гистограммы + площадь изменений >25%; плавные переходы — по промежуточным кадрам.
- Метаданные (`probe`): неявные метки AIGC, C2PA, подписи редакторов, пометки перекодирования платформой (`Tencent CAPD MTS`, `Wxmm_`, `vid:v…` -> `video_context.transcoded`). Эти маркеры специфичны для китайских платформ; для Instagram/TikTok/YouTube — проверить.
- Перекодированное видео стирает шум сенсора, поэтому «нет шума» не доказывает ИИ; такие шоты получают статус «снято или ИИ — на проверку». Уверенность без явных артефактов ИИ — не выше 0.7 (review.md). Платформенная перекодировка конкурентских роликов с наших площадок будет именно такой — главный практический риск точности.
- Звук (audio.md): гармоническая доля >0.62 -> музыка; основная частота <150 Гц мужской, >200 Гц женский голос; доля выдержанных нот >0.3 -> пение; доля повторов припева >0.1 -> песня; вероятность <45% -> «на проверку».
- Метрики точности на eval-наборах (eval/RESULTS.md) — не читались, проверить.

## Библиотеки и программы
- Python >=3.10 (по install-скрипту до 3.14; для onnxruntime на слишком новом Python нет wheels). Системные: ffmpeg, ffprobe. Для PDF: Chrome/Chromium/Edge.
- Ядро (pyproject.toml): numpy>=1.24,<3; opencv-python-headless>=4.8,<5; Pillow>=9.0; PyYAML>=6.0; videomd>=1.1; onnxruntime>=1.16.
- Extra `ocr`: rapidocr-onnxruntime>=1.3,<2 (Python <3.13) или rapidocr>=3.4,<4 (Python >=3.13). Тянет GUI opencv-python, конфликт с headless, install_skill.sh чинит сам; вручную: `pip uninstall -y opencv-python && pip install --force-reinstall --no-deps "opencv-python-headless>=4.8,<5"`.
- Extra `asr`: sherpa-onnx>=1.12. Extra `dev`: pytest>=7, jsonschema>=4.
- Для `drive --depth`: transformers + torch (не в extras).
- Скачивается при первом запуске в `$REA_VIDEO_MODELS` (по умолчанию `~/.cache/rea-video/models`):
  - UVR MDX-Net Inst HQ 3 (вокал/музыка) ~67 МБ;
  - BandIt v2 multilingual (эффекты) ~149 МБ, CC BY-SA 4.0, работает ~1.5x длительности аудио; при ошибке загрузки эффекты ищутся в общем миксе;
  - SenseVoice (ASR) ~160 МБ (только с extra asr);
  - pyannote segmentation 3.0 + 3D-Speaker CAM++ (разделение говорящих) ~35 МБ суммарно (только с asr);
  - бенгальский потоковый ASR ~90 МБ (`--asr-lang bn`);
  - OCR: английская модель ~8 МБ, японская ~10 МБ, корейская PP-OCRv5 ~14 МБ (по запросу `--ocr-lang`); размер базовой китайско-английской модели RapidOCR в документах не указан — проверить.
- Время: 30-секундное видео ~1 минута без VLM (docs). `--no-packaging` экономит ~30-50 с на минуту видео. Потоки: `REA_VIDEO_THREADS`, максимум 8.
- Откуда качаются модели (HuggingFace/GitHub releases) — проверить; важно для среды без доступа или с прокси.

## Внешние сервисы и модели
- Обязательно: ничего. Режим «только инструменты» работает офлайн и бесплатно (README).
- Необязательно, VLM: любой OpenAI-совместимый эндпоинт. Переменные `REA_VLM_BASE_URL`, `REA_VLM_API_KEY`, `REA_VLM_MODEL` (через запятую — список с откатом). Запасные: `VIDEO_ANALYSIS_*`, `GEMINI3_*` (из capsule-cinema); только Gemini: `GEMINI_API_KEY` + `REA_GEMINI_MODEL`. Упомянуты Gemini, GPT-4o, Doubao, Qwen-VL. Файл подключается `--env-file`. Лимит 60 вызовов VLM на разбор (`--max-vlm-shots`). Для `moments` только Gemini (или видео-VLM) получает клип со звуком; видео загружается в Google и удаляется после использования. Цена — по тарифу провайдера.
- Необязательно, генерация/пересъёмка: capsule-cinema + ключи моделей в его `.env`. Платно по вызовам; `--dry-run` и подтверждение пользователя обязательны по скиллу. По умолчанию для плана пересъёмки в README указана MiniMax H3; в примерах `seedance-2.5`.
- ChatCut (спонсор проекта, через него в SKILL.md рекомендуется редактирование): настольное/веб-приложение, генерация за кредиты, членство. Реклама в references/remake-tools.md — учесть при копировании скилла.
- HyperFrames (HeyGen, Apache-2.0, Node 22+) — упомянут как инструмент пересъёмки, не зависимость.
- Телеметрии/других обязательных облаков в прочитанных файлах не найдено; в коде не проверялось — проверить.

## Работа без Gemini
Да, работает; без платной подписки Gemini. Три режима:
1. Только детерминированный: `decompose ref.mp4 -o out/ref` — без VLM, без сети (кроме разовой загрузки моделей). Вердикт по метрикам и метаданным; без картинок помечает неоднозначное как «на проверку».
2. Агент как VLM (то, что нужно нам): `survey` -> `decompose` -> `review` -> агент смотрит картинки -> `apply-review`. Веб/API Gemini не нужны.
3. Любая OpenAI-совместимая VLM через `REA_VLM_*` (не только Gemini).

Что делает агент на шаге review:
- Читает `review_tasks.json`: на каждый шот — что смотреть, оценка инструмента (label_probs кандидатов), приоритет, историю правок, команды `frame_cmd`. Поле `instructions` — правила.
- Смотрит файлы: `storyboard.jpg` (общая раскадровка), `audio.png`, `shots/shot_XXX.jpg` (первый, средний, последний кадр шота), при сомнении кадры из `tiles` (шаг по умолчанию в примере 0,1 с), `packaging/sticker_XX.jpg`, `stems/vocals.wav` и `music.wav` (звук — слушать нельзя текстовому агенту, см. слабые места), `video/cast.md`. Для шотов `priority=high` просмотр обязателен.
- Сколько кадров: единой цифры в прочитанных файлах нет. По структуре: 3 кадра на шот + storyboard + доп. кадры tiles по необходимости. Для `survey`: контактные листы, каждое изображение заполняется до ~1568 px (~1.15 MP) с максимумом ячеек; до 3 раундов; половина ячеек равномерно, половина там, где кадр меняется сильнее. Для 60-секундного Reels число картинок и токенов — проверить на реальном прогоне.
- Заполняет `review_answers.json`: `label_probs`, `evidence`, `description`, `narrative` (role из 8 значений + point), `embedded_assets`, `split_suggestion` (cuts/labels/note), `overlay_text`, `same_clip_as`, верхний уровень `cast`, стиль, `story` (summary, hook, highlights 2-4), `aspects` (ракурс, штатив/селфи, свет, оборудование), `packaging.stickers/missed/text`.
- `apply-review` сливает; расхождения с инструментом агент объясняет в ответе.
- Если агент не умеет читать изображения: review.md велит не пересматривать выводы инструмента и только проверять склейки, OCR, уровни stems, метаданные.
- Ограничения: DeepSeek-модели текстовые (мультимодальность у конкретной модели — проверить); в этом случае работает только режим 1 (без картинок) либо отдельная VLM через `REA_VLM_*` (например Qwen-VL, GPT-4o).

## Русский язык
- Язык отчёта: только `zh` (по умолчанию) и `en`. Русского нет. Рекомендация скилла для остальных языков: `--lang en` и ответ агента на языке пользователя; копия отчёта на другом языке хранится как `report_<язык>.md`. Поля `*_zh` в breakdown.json сохраняют имена, содержимое — на языке отчёта. Значит в report.html/VIDEO.md будет английский, а русский пишет агент.
- ASR: SenseVoice через sherpa-onnx. Языки по документации: китайский, английский, японский, корейский, кантонский. Русского нет. Для не поддерживаемого языка (в доках про бенгальский) SenseVoice «принимает его за английский, японский или корейский» — то есть на русской речи даст мусор. Отдельной русской модели в проекте нет. Вывод: транскрипт русской речи этим инструментом не получить; нужен внешний ASR (например Whisper/GigaAM/Vosk), подключается вне rea-video — проверить, можно ли подложить свои реплики в `speech.lines`.
- OCR: RapidOCR (PP-OCR), базовая модель китайско-английская; опции `--ocr-lang`: zh, en, ja, ko. Кириллицы нет в списке; PP-OCRv5 имеет отдельную кириллическую (eslav) модель, но подключение через `$REA_OCR_REC_MODEL` для русского в документах не описано — проверить (по докам этот параметр указан для офлайн-японской модели). Русские субтитры/надписи, скорее всего, не распознаются; анализ упаковки (тайминг субтитров по OCR) для русских видео ненадёжен.
- Язык SKILL.md и references: английский (README и docs/en на английском; часть терминов в review.md/materials.md и значения полей остаются китайскими: «待确认», «复刻时需要你提供» и т.п.). Китайские строки в выдаче пакета VIDEO.md возможны при lang=zh. Есть i18n/ README, в т.ч. русский (не открывался).
- Метки платформ в метаданных — китайские (WeChat, Douyin); на Reels/Shorts/TikTok (международный) проверить.

## Агенты, в которых работает

OpenCode и Kimi Code скриптом не покрываются: нужно вручную положить/залинковать папку скилла в их каталог скиллов (путь для Kimi Code и OpenCode — проверить).

  4. Тяжёлые зависимости (onnxruntime, opencv, ~250-400 МБ моделей), Python 3.10-3.14; Windows — через junction.
  5. Скилл большой: SKILL.md + 9 references; рекомендованная экономия токенов (VIDEO.md ~2 тыс. токенов) помогает, но на слабой модели инструкция длинная.

## capsule-cinema
- https://github.com/JuneYaooo/capsule-cinema, Apache-2.0. Система производства коротких видео, ставится как скилл в агент (Codex, Claude Code, OpenClaw, Cursor, Trae, Hermes Agent). Рецепты (`life_sim`, `ecommerce_product_showcase`, `art_motion`, `repo_signal_grid`), проверка формата, чёрных кадров, громкости, субтитров; перегенерация отдельного шота. Ориентирован на китайских авторов. Нужны Python 3.12 и FFmpeg; браузер (Playwright) — только для интро-ролика проекта.
- Модели генерации: изображения — Volcano Ark Seedream, Agnes Image 2.1 Flash; видео — Volcano Ark Seedance (720p по умолчанию), MiniMax H3 (2K по запросу), Agnes Video v2.0, RunningHub H3; голос — Doubao, MiniMax; перенос движения и lip-sync — RunningHub; монтаж/субтитры/QA — локальный FFmpeg.
- Цена: своих мощностей нет, платите по ключам каналов. Первое видео без ключей (локальные шаблоны, раскадровка). У Agnes есть бесплатный тариф (в README: ограничения, например ~1 запрос видео в минуту, без SLA).
- Доступ из РФ, оплата и качество русской речи/текста в генерации для Seedance/MiniMax/Doubao — проверить.
- Связка с rea-video: rea-video запускает `scripts/remake_reference.py` capsule-cinema в его Python-окружении; корень задаётся `prefs capsule_root` / `--capsule-root` / `CAPSULE_CINEMA_ROOT`; интерпретатор: `--python` -> `$CAPSULE_CINEMA_PYTHON` -> `<root>/.venv/bin/python`. Статичные кадры с панорамой/зумом пересобираются локально без модели. Субтитры и стикеры вырезаются из референсов и возвращаются `assemble --overlays`.
- Для нас: пересъёмка не нужна (мы генерируем сами на шаге 8), берём только идею плана/промптов.

## Слабые места
- Нет русского: ASR (SenseVoice) и OCR (zh/en/ja/ko) не поддерживают кириллицу; язык отчёта zh/en. Для наших роликов транскрипт и субтитры придётся делать другим инструментом.
- Точность вердикта на роликах, скачанных с Reels/Shorts/TikTok (перекодирование, нет шума, пересжатие), снижена; сам проект это признаёт (статус «снято или ИИ — на проверку», уверенность ≤0.7). Заявленные метрики eval не проверены.
- Метаданные-улики заточены под китайские платформы.
- Объём работы агента на review большой (задание на каждый шот, JSON с множеством полей); на слабых/текстовых моделях (DeepSeek) не заработает без VLM. Число кадров на видео не нормировано.
- Проект молодой: версия 0.1.0, релизов и тегов нет, дату последнего коммита не видно, тесты скрыты в .gitignore (в репо их нет). Звёзд 12.2k, 192 коммита.
- Документация расходится сама с собой: Remotion-проект в README и «не генерируется» в cli.md; `~/.gemini` в cli.md и нет в install_skill.sh.
- README предупреждает о мошенниках с токенами под именем проекта; проект крипту не выпускал — это не риск кода, но фон репутации.
- Рекламный элемент (ChatCut) встроен в тексты скилла.
- onnxruntime без wheels на слишком свежем Python; конфликт opencv требует ручного шага вне install_skill.sh.
- Исходники модулей не читались (robots.txt на github.com/tree): утверждения о порогах взяты из документации, не из кода.
