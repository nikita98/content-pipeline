# kp-bench — тестовый стенд

Задача стенда — честно сравнить варианты из `site/data/stack.json` со статусом «в тест» на одном материале и сохранить результаты так, чтобы владелец проекта выбрал инструмент по цифрам. Тестируют несколько человек на разных компьютерах. Каждый прогон — отдельный файл, поэтому результаты не конфликтуют в git.

## Что где
- `site/data/bench.json` — каталог: тесты, варианты, метрики, цены, бесплатно или платно.
- `references/tests.md` — порядок каждого теста и как считать метрики. Читай раздел нужного теста перед запуском.
- `references/install.md` — установка под Windows и macOS. Читай, когда инструмента нет или он падает.
- `assets/inputs/` — общий материал: текст для записи и синтеза, эталон для WER, строки для ударений, пост с заложенными проблемами и ключ к нему.
- `scripts/` — CLI на Python без зависимостей (кроме самих тестируемых библиотек):
  - `check_env.py` — среда тестировщика;
  - `asr_run.py` — распознавание с общим форматом слов;
  - `wer.py` — точность;
  - `loudness.py` — громкость;
  - `stress_run.py` — ударения;
  - `captions.py` — субтитры для монтажа;
  - `blind.py` — слепая оценка;
  - `record.py` — запись результата;
  - `summary.py` — свод.
- `bench/runs/` — тяжёлые выходные файлы, в git не идут. `bench/results/` — результаты прогонов, в git идут.

## Интерфейс
Для людей без терминала есть локальная страница: `start.bat` (Windows) или `start.command` (macOS) в корне репозитория, раздел «Тесты» — `start-bench.bat` / `start-bench.command`. Устройство — `app/README.md`. Интерфейс запускает те же скрипты из `scripts/`, пишет результаты через `record.py` и `summary.py`, отправляет их в git или отдаёт архивом. Шаги с ИИ (ru-text, монтаж) он запускает через агента, выбранного в «Настройках». Если тестировщик работает в интерфейсе, в агенте повторять прогон не нужно: результаты уже в `bench/results/`.

`scripts/tts_qwen.py` — синтез Qwen3-TTS с клоном (код из install.md, раздел 5); на GPU не запускался — проверить.

## Как вести сессию
1. **Кто тестирует.** Спроси имя тестировщика латиницей (`nikita`, `anna`) и запусти `python skills/kp-bench/scripts/check_env.py --tester <имя>`. По выводу реши, что доступно: без NVIDIA варианты Qwen3-TTS пропускаются, распознавание идёт на CPU.
2. **Что осталось.** Запусти `summary.py`, сравни с каталогом (`record.py --list`) и покажи, какие тесты и варианты ещё без результатов у этого человека. Предложи следующий по порядку из `references/tests.md`. Бесплатные идут раньше платных.
3. **Нужна ли запись.** Для asr, voice-clean, tts и edit нужна запись эксперта по `script_ru.txt`. Если её нет, объясни, как записать (раздел «Подготовка» в tests.md), и предложи пока text-check или stress — им запись не нужна.
4. **Прогон.** Выполняй команды сам, если в этом агенте есть терминал на компьютере тестировщика. Если нет — давай команды по одной, проси прислать вывод и разбирай ошибки. Время установки засекай отдельно от времени прогона: оба числа важны для выбора.
5. **Оценки человека.** Естественность голоса, липсинк, синхрон субтитров ставит человек по шкале из tests.md, где можно — вслепую через `blind.py`. Не ставь эти оценки за человека и не подсказывай, какой файл какой. Иначе сравнение теряет смысл.
6. **Запись.** После каждого варианта — `record.py` с метриками, вердиктом и заметкой: что сломалось, что пришлось обойти, на каком железе. Если вариант не запустился, тоже записывай с `--verdict fail` — это результат.
7. **Свод и git.** В конце сессии — `summary.py`, затем `git add bench/results bench/env site/data/bench_results.json`, коммит по-русски («Стенд: asr у nikita — GigaAM, faster-whisper») и `git pull --rebase` перед `git push`.

## Платные тесты
tts-cloud, asr-cloud, avatar, clips — это расход денег. Перед каждым прогоном:
- назови сумму из `test_cost` в каталоге;
- предупреди, если цена помечена «проверить»;
- дождись явного «да» от того, кто платит.

Без «да» ничего не генерируй — даже «один пробный». Фактическую сумму запиши в `--cost`. Ключи API вводит человек в своё окружение (переменные или `.env`). Не проси вставлять их в чат и не записывай в файлы репозитория.

## Голос эксперта
Клон голоса делается только при письменном согласии владельца голоса. Если запись чужая и согласия нет — тестируй синтез готовыми голосами, клон пропусти и отметь это в заметке.

## Что не делать
- Не менять `assets/inputs/` между тестировщиками: иначе цифры несравнимы. Если материал неудачный — предложи владельцу новую версию отдельным коммитом и пометь в заметках, с какой версии считались результаты.
- Не выбирать победителя. Стенд даёт цифры и наблюдения, решение — за владельцем проекта (`decisions.json`).
- Не коммитить аудио, видео, модели и `.venv-*`.
